Demo phát hiện anomaly realtime logs-only bằng Kafka

Tài liệu này gồm các bước demo realtime anomaly alert bằng Kafka + Spark Structured Streaming cho project Train-Ticket. Demo dùng logs-only model artifact đã train từ Sprint 4.

Mục tiêu

Replay structured log từ dataset Train-Ticket vào Kafka topic train-ticket-logs, Spark streaming đọc log theo window 60 giây, tính logs-only features, load model baseline_logs_only_logistic_regression, sau đó đẩy alert sang topic train-ticket-alerts nếu probability vượt threshold.

1. Điều kiện trước khi demo

  • Chạy trong WSL Ubuntu tại thư mục /mnt/d/projects/big-data.
  • Kafka đang chạy tại localhost:9092.
  • Đã cài Python dependency kafka-python trong virtualenv hoặc môi trường đang dùng.
  • Đã có model artifact: reports/models/artifacts/baseline_logs_only_logistic_regression.
  • Nếu chưa có artifact, chạy lại baseline training trước khi demo.
cd /mnt/d/projects/big-data
bash scripts/run_baseline_models.sh

2. Start Kafka server bằng KRaft mode

Nếu Kafka chưa chạy, mở một terminal riêng và start Kafka bằng KRaft mode. Bước format storage chỉ cần làm lần đầu sau khi giải nén/cài Kafka hoặc khi muốn tạo lại cluster mới.

Vào thư mục Kafka

cd ~/kafka

Tạo cluster id

KAFKA_CLUSTER_ID="$(bin/kafka-storage.sh random-uuid)"
echo $KAFKA_CLUSTER_ID

Format Kafka storage

bin/kafka-storage.sh format \
  --standalone \
  -t "$KAFKA_CLUSTER_ID" \
  -c config/server.properties

Start Kafka server

bin/kafka-server-start.sh config/server.properties
Lưu ý: Terminal start Kafka server phải được giữ đang chạy trong lúc demo. Nếu storage đã format rồi, lần sau thường chỉ cần chạy lệnh start server.

3. Tạo Kafka topics

Chỉ cần tạo một lần. Nếu topic đã tồn tại thì Kafka sẽ báo đã có, có thể bỏ qua.

cd ~/kafka
bin/kafka-topics.sh \
  --bootstrap-server localhost:9092 \
  --create \
  --topic train-ticket-logs \
  --partitions 1 \
  --replication-factor 1

bin/kafka-topics.sh \
  --bootstrap-server localhost:9092 \
  --create \
  --topic train-ticket-alerts \
  --partitions 1 \
  --replication-factor 1

4. Demo chính bằng 3 terminal

Thứ tự nên dùng: Terminal 1 chạy Spark alert job, Terminal 2 nghe alert, Terminal 3 mới replay logs.

Terminal 1 - Spark streaming alert job

cd /mnt/d/projects/big-data
bash scripts/run_logs_only_streaming_alerts.sh \
  --threshold 0.5 \
  --output-mode kafka \
  --starting-offsets latest \
  --checkpoint-dir data_lake/checkpoints/logs_only_alerts_demo

Terminal này đọc topic train-ticket-logs, tính feature theo window, predict anomaly probability, rồi ghi alert vào train-ticket-alerts.

Terminal 2 - Kafka alert consumer

cd ~/kafka
bin/kafka-console-consumer.sh \
  --bootstrap-server localhost:9092 \
  --topic train-ticket-alerts \
  --from-beginning

Terminal này sẽ hiện JSON alert khi Spark ghi kết quả sang topic alert.

Terminal 3 - Replay logs vào Kafka

cd /mnt/d/projects/big-data
python scripts/produce_logs_to_kafka.py \
  --limit 2000 \
  --sleep-seconds 0.001

Producer mặc định đọc file log structured của case case_01_admin_basic_info_spring_1_5_22 và gửi vào topic train-ticket-logs.

6. Chế độ debug console

Nếu muốn xem cả normal và anomaly ngay trên Terminal 1, dùng console mode. Chế độ này không ghi vào topic train-ticket-alerts. 

cd /mnt/d/projects/big-data
bash scripts/run_logs_only_streaming_alerts.sh \
  --threshold 0.5 \
  --output-mode console \
  --emit-all \
  --starting-offsets latest \
  --checkpoint-dir data_lake/checkpoints/logs_only_alerts_demo_console
Lưu ý: Nếu chạy --output-mode console, Kafka consumer ở Terminal 2 sẽ không thấy alert vì job chỉ in ra console. Muốn đẩy alert sang topic thì phải dùng --output-mode kafka.

7. Xử lý lỗi thường gặp

  • Consumer không thấy alert: kiểm tra Terminal 1 có dùng --output-mode kafka không. Console mode không ghi alert topic.
  • Không thấy row nào: dùng checkpoint mới hoặc đổi --starting-offsets earliest để đọc lại message cũ.
  • Cần chắc chắn có alert: hạ threshold xuống 0.01 trong lúc demo; sau đó giải thích threshold thực nghiệm của logs-only baseline là 0.96.
  • Checkpoint bị state cũ: đổi sang checkpoint mới, ví dụ data_lake/checkpoints/logs_only_alerts_demo_2.
  • Cần đọc message cũ trong topic: dùng --starting-offsets earliest và checkpoint mới.

8. Nội dung đưa vào báo cáo

Demo Kafka logs-only là phần mở rộng realtime của pipeline batch. Pipeline chính vẫn là bronze/silver/gold + model training + dashboard. Streaming demo chứng minh model artifact có thể được tái sử dụng cho inference gần realtime trên telemetry mới.

  • Kafka đóng vai trò message broker nhận log events realtime.
  • Spark Structured Streaming đóng vai trò online feature engineering và inference.
  • Model artifact logs-only Logistic Regression được load từ reports/models/artifacts.
  • Alert JSON gồm service, time window, probability, threshold và các feature logs-only.
  • Bản demo dùng static dataset để replay thành stream, vì dataset gốc không phải live telemetry.
